export TF_VAR_do_token="dop_v1_REPLACE_ME"
export TF_VAR_spaces_access_id="DO00REPLACEME"

Never commit these to git. Add them to your shell's secret-loader (1Password CLI, direnv with .envrc-private, etc.) so they survive new sessions but stay out of history.
3 Bootstrap: Project + state bucket ~10 min

Run this once per DO account. Creates the YesCare Production Project and the Spaces bucket that holds prod Terraform state — and attaches that bucket to the project.

cd digitalocean/envs/bootstrap-prod

cp terraform.tfvars.example terraform.tfvars
# Edit terraform.tfvars only if you want a different project name
# or state bucket name. Defaults work for first run.

terraform init -input=false
terraform apply
Expected resources: digitalocean_project.prod, digitalocean_spaces_bucket.tf_state, digitalocean_project_resources.tf_state_bucket. The apply prints project_id and state_bucket_name — copy both.
# Save outputs for the next section
terraform output -raw project_id
terraform output -raw state_bucket_name
State safety: bootstrap-prod/terraform.tfstate is local and gitignored. Back it up to 1Password (or your team vault). Losing it means manually re-importing the Project + bucket later.

5 Apply Pass 1: cluster + managed services ~25 min

First pass creates the DOKS cluster and the managed databases. Helm releases are skipped because the kubeconfig doesn't exist yet.

terraform init \
  -backend-config="access_key=$TF_VAR_spaces_access_id" \
  -backend-config="secret_key=$TF_VAR_spaces_secret_key"
terraform apply \
  -target=module.vpc \
  -target=module.kubernetes \
  -target=module.postgres \
  -target=module.redis \
  -target=module.spaces \
  -target=module.firewall \
  -target=digitalocean_project_resources.prod_scale
Time: Postgres HA takes ~5 min, DOKS ~5-8 min, Redis ~3 min. Run all in parallel above — Terraform handles the dependency graph.

Sanity check:

doctl kubernetes cluster list
doctl databases list

7 Apply Pass 2: Helm releases ~15 min

Second pass installs ingress-nginx (triggers DO LB), cert-manager, Kafka, and the Let's Encrypt ClusterIssuer.

kubectl get pods -A -w

kubectl get svc ingress-nginx-controller -n ingress-nginx \
  -o jsonpath='{.status.loadBalancer.ingress[0].ip}'

If your registrar can't delegate the whole zone to DO, use Cloudflare-fronting instead: orange-cloud the DNS records pointing to the DO LB IP, and skip the DO Domain module (leave domain_name empty in tfvars).
10 Configure CD pipeline for prod ~25 min

The workflow file is already in the repo: .github/workflows/terraform-do-prod-scale.yml. It mirrors the existing dev pipeline pattern: plan on PR, apply on push to main with a manual approval gate.

GitHub repo → Settings → Secrets and variables → Actions → New repository secret. Add these 5:

Secret nameValue
DO_TOKEN_PRODDO API token (prod-only, write scope)
DO_SPACES_ACCESS_IDSpaces access key
DO_SPACES_SECRET_KEYSpaces secret key
DO_PROJECT_ID_PRODproject_id output from bootstrap-prod
LETSENCRYPT_EMAILops@yescare.in (optional)

GitHub repo → Settings → Environments → New environment → name do-production:

  • Required reviewers: at least 1 person from the ops team
  • Deployment branches and tags: Selected branches and tags → main
  • Wait timer: optional 5-minute buffer to allow cancel
After secrets + environment are set, every PR that touches digitalocean/envs/prod-scale/** posts a Terraform plan as a comment. Merges to main wait for reviewer approval before applying.
kubeconfig handling: The workflow uploads kubeconfig-prod-scale.yaml as an artifact. Set artifact retention to 7 days max and use GitHub Environment Secrets for runtime app deployment workflows — never check kubeconfig into git.
11 App connection strings & secrets ~15 min

Pull connection details from terraform output and put them into a Kubernetes Secret your app reads.

cd digitalocean/envs/prod-scale

# Postgres
terraform output -raw database_host
terraform output -raw database_user
terraform output -raw database_password
terraform output -raw database_name

# Redis
terraform output -raw redis_host
terraform output -raw redis_password

# Kafka
terraform output kafka_bootstrap_servers

# Spaces
terraform output spaces_endpoint
terraform output spaces_app_bucket
kubectl create namespace app --dry-run=client -o yaml | kubectl apply -f -

kubectl create secret generic yescare-prod-config \
  --namespace=app \
  --from-literal=DB_HOST="$(terraform output -raw database_host)" \
  --from-literal=DB_USER="$(terraform output -raw database_user)" \
  --from-literal=DB_PASS="$(terraform output -raw database_password)" \
  --from-literal=DB_NAME="$(terraform output -raw database_name)" \
  --from-literal=REDIS_HOST="$(terraform output -raw redis_host)" \
  --from-literal=REDIS_PASS="$(terraform output -raw redis_password)" \
  --from-literal=KAFKA_BOOTSTRAP="kafka.messaging.svc.cluster.local:9092" \
  --from-literal=S3_ENDPOINT="$(terraform output -raw spaces_endpoint)" \
  --from-literal=S3_BUCKET="$(terraform output -raw spaces_app_bucket)"

13 Disaster recovery & rollback reference

Bad terraform apply: Spaces backend has versioning on. Roll back via:

# List versions
s3cmd --host=sgp1.digitaloceanspaces.com --host-bucket="%(bucket)s.sgp1.digitaloceanspaces.com" \
  --access_key=$TF_VAR_spaces_access_id --secret_key=$TF_VAR_spaces_secret_key \
  ls s3://yescare-tfstate-prod/envs/prod-scale/

# Restore a specific version
# (use DO console UI — easier than CLI for one-off restores)

Helm rollback (Kafka, ingress, cert-manager):

helm history kafka -n messaging
helm rollback kafka 1 -n messaging

Postgres point-in-time restore: DO Console → Databases → your cluster → Backups → Restore. Default retention 7 days; extend to 30+ for production.

Total infra destroy (use with extreme care):

# Only after taking final snapshots
terraform destroy -var="kubeconfig_path=kubeconfig-prod-scale.yaml"
# Then cd ../bootstrap-prod && terraform destroy
Order matters: always destroy prod-scale before bootstrap-prod. Otherwise the state bucket disappears while you still need it.
